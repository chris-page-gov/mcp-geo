# Release 0.8.0

Date: 2026-04-23

## Summary

`0.8.0` pins the current MCP-Geo strategy baseline before a possible larger
direction change. It packages all merged work since `0.7.0` on current `main`,
including LandIS phase-2 surfacing, AddressBase/Council Tax runtime expansion,
ONS geography cache hardening, task-shaped OS map exports, unattended
multi-client evaluation tooling, and OS NGD Spring 2026 compatibility.

## Strategic Baseline

- Task-shaped MCP tools are the preferred client strategy where low-level
  orchestration has proved fragile, especially for map export, area summary,
  resource handoff, and multi-step property-tax workflows.
- Local-data-first runtime paths remain the default for bulky or licensed data:
  PostGIS stays in place for boundary/LandIS/routing workloads, while DuckDB is
  now used for AddressBase Parquet lookup where file-backed analytical access is
  the simpler fit.
- Client interoperability is now measured with readiness-first unattended
  evidence across Codex CLI, Gemini CLI, Claude Code CLI, and VS Code Agent.
- Docker-backed host wrappers default to isolated sidecars, with shared
  devcontainer/cache reuse treated as explicit opt-in.
- Known caveats carried into this stable pin: existing ONS UPRN caches built
  before the multi-shard fix still need rebuild, and the VS Code unattended
  cleanup path still needs one fresh live rerun before that remediation is
  fully closed again.

## Highlights

- Added LandIS MVP and phase-2 tool families, archive manifests, local archive
  ingestion/bootstrap support, and checked-in LandIS/Obsidian knowledge bases.
- Added `council_tax.band_lookup` and `council_tax.query`, including DuckDB
  Parquet support for AddressBase Premium cross-reference lookups.
- Added resolver-driven ONS geography source acquisition, semantic geography
  normalization, cache freshness/provenance reporting, release audit support,
  and the ONSUD/NSUL multi-shard UPRN ingest fix.
- Added `ons_geo.area_summary` and compact `os_map.inventory` summary/count
  modes for small-area profile follow-ups.
- Added `os_map.export_roads` as a durable semantic road-overlay export
  contract, including resource-backed GeoJSON/JavaScript/Leaflet artifacts.
- Added readiness-first unattended client evaluation tooling and evidence
  reports under `docs/reports/client_interop_unattended/`.
- Added OS NGD Spring 2026 support for GB postcode unit area/point, bus lane,
  and cycle lane layers, plus optional OS API header/bearer auth modes.
- Hardened raw HTTP auth coverage, secret redaction, local quality wrappers,
  OWASP validator compatibility, and playground validation.
